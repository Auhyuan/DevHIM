# Brainstorming

Help the developer decide what to build, what comes first, and what is enough. Start when asked to explore. If the requirement is clear, summarize it and return to the current workflow. Resolve missing facts, sources, or permissions directly.

## Find the decision that matters

- Reuse the supplied context. In an existing project, read only the relevant state, requirements, screens, or code. Answer from those sources where possible. Ask a follow-up only if the answer would change a decision. Distinguish facts, inferences, and proposals.
- Start with a short restatement and one question that could change the direction. If the purpose is unclear, ask who faces what problem in which situation. Otherwise, use a concrete scenario to clarify a behavior, boundary, or trade-off.
- Carry forward agreed constraints. If discussion stalls, turn the disagreement into an observable example and show how choices change the user experience or initial scope. If it remains open, identify the open question and the information needed to decide it.

## Compare and narrow

- When asked for ideas, give a few distinct directions with their use cases and costs. When a choice is needed, recommend one and name the assumption or constraint that could change it. Give one option if only one is viable.
- Restate the direction using the first users, key flow, deferred scope, and an observable success criterion. Use a short diagram or text sketch only if it helps the decision. If the user asked only for ideas, stop with comparable options.
- Leave material trade-offs to the user. If they delegate a decision, label your recommendation as an agent decision and explain the basis. Keep unresolved items pending and reserve confirmed AC for agreed requirements.

## Handoff

Summarize the agreed goal, first scope, deferrals, success criteria, and open decisions in the user's working language. Include only what the next step needs.

When invoked from P-SOP, return to REQUIREMENTS for confirmation. With existing write authorization, merge useful conclusions into the current REQ or AC entry. Keep new brainstorming documents, conversation logs, and design drafts outside the default output. When used on its own, hand the summary to the user.

Brainstorming is scoped to exploration. Prototypes, implementation, verification, Git operations, and external writes require their own authorization.
