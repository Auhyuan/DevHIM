# 开发周期与 Gap

供状态维护与看板展示共同使用。按以下五字段顺序展示时间与推进内容，保持数值简短；计算和维护规则留在 Skill，不逐项复制到项目状态。

## 输出约定

本分区按“标题 → 一行统计截至时间及其时区 → 五字段 → 等级说明”输出。PROJECT-STATE.md 使用五行 Markdown 表格，看板保留同顺序的五项展示；字段名称与顺序沿用下表，最后一项单独记录推进内容。

“等级说明”必须使用四条独立列表，依次为 NORMAL、REMINDER、WARNING、LONG_GAP；每条只说明中文含义与时间区间，采用状态模板中的措辞。看板使用对应的四个列表项，不合并成一个长段落。用户自定义阈值时同步区间，默认边界不变。

不附加“时间依据”“计算过程”“维护规则”等说明段，也不复述“包括失败结果”“历时包含中断”或已有 Git 基准等规则。起始基准直接写在项目起始值中，历时值仅写时长，推进时间值仅写时间；最近一次有效推进内容保留一句实际工作摘要。

时间缺口优先在对应字段写未记录、无法计算或实际精度；确需补充时，只在列表后附一句具体缺口，例如“历史推进时间仅记录到日期”。没有缺口就不生成短注，不写“时间依据完整”等占位结论。排期与操作授权放当前交付、工作或边界部分，不附加到此分区。

## 字段与时间口径

| 固定字段名 | 展示内容 |
|---|---|
| 项目起始 | 时间；已有项目接入时注明“以 Git 最早提交为基准” |
| 项目历时（包含中断时间） | 仅时长，例如 `20 天 2 小时`，值中不重复解释 |
| 最近一次有效推进 | 仅实际发生时间，不拼接工作描述 |
| 距上次推进 | 时间差与英文等级，例如 **9 天 2 小时 · WARNING** |
| 最近一次有效推进内容 | 一句实际工作结论，放表格最后一行，与推进时间对应 |

新项目使用实际起项时间；已有项目接入使用项目 Git 历史中最早提交的时间作为起始基准，首次确定后沿用，不在每次更新时重新扫描历史。无 Git 写未记录；历史不完整时注明“当前可追溯最早提交，历史不完整”，不自动拉取历史。SOP 首次接入仍独立记录在项目身份信息中，不代替项目起始。人工更正起始时间后沿用更正值及其依据。

项目采用统一时区，默认 `Asia/Shanghai`，时间格式 `YYYY-MM-DD HH:mm:ss`，每处时间分区标明时区和统计截至时间。历史资料只有日期或分钟精度时保留真实精度，不补造秒；精度不足以判断边界时标待核对。状态核对、页面生成时间与推进时间分别表达。

用户设定交付日期时在当前交付或风险中表达，Agent 不推测截止日期。此时间分区只保留上述五项，不保留最近一次恢复、恢复前中断或恢复提醒，不另建历史中断记录。用户可人工更正时间，更正后重算受影响时长，更正操作本身不算推进。

## 计算与更新

按完整时间差计算，一天为连续 24 小时，包含周末与节假日；先判断等级，再把时长展示为天、小时等易读形式，不先取整。页面是截至标注时刻的快照，不要求实时计时或后台刷新，也不为刷新数值反复修改文件。

```text
项目历时（包含中断时间） = 本次实际计算时间 − 项目起始时间
距上次推进 = 本次实际计算时间 − PROJECT-STATE.md 中最近一次有效推进时间
```

更新状态或生成看板时，Agent 根据本次实际时间及已有时间记录计算时长和等级，不凭感觉估计，不把旧的 Gap 数值当作当前结果。仅查看或刷新展示时保留推进时间；发生有效推进后，同时更新推进时间与对应内容，再计算距上次推进，此时接近零是正常结果，无需保存此前中断长度。仅生成看板不能改写源文档的推进时间；没有 PROJECT-STATE.md 时使用现有资料中的对应推进记录，不为此创建状态文件。

例如推进时间为 `2026-10-01 12:50:59`，统计截至 `2026-10-10 14:50:59`，展示 **9 天 2 小时 · WARNING**；若发生新的有效推进，按更新后的推进时间重新计算。

以下是有效推进：需求确认、关键方案或范围决定、实际实现与修复、获准验证取得结果（包括失败）、完成恢复梳理并明确当前状态与下一步。只记录实际工作的发生时间，补录不使用补录时刻替代。

打开项目、纯阅读、询问进度、排版、刷新看板、修改时间字段，以及无实质结果的重复操作，都不重置 Gap。恢复梳理包含范围、实现与任务的明确结论，不能以一次读取冒充完成。

缺少最近推进记录时写无法计算；起项时确有工作发生，才可将起项作为首次推进。历史记录不完整时在分区下注明依据缺口，不改固定字段名，不推定期间完全没有开发。时间倒置、未来时间或时区不明导致无法比较时标待核对，不归零或自行修正。项目历时是包含中断的日历跨度，默认不统计开发工时或累计阻塞时长。

## 默认等级与提醒

以下是可配置的协作提醒阈值，不是证明项目失控或知识丢失的标准。用户可按开发节奏调整，Agent 不自行推测或改档；自定义边界应明确、连续且不重叠。

| 完整时间差 | 英文等级 | 中文含义与建议 |
|---|---|---|
| `< 72 小时`（不足 3 天） | NORMAL | 正常接续；展示时间即可，无需主动提醒 |
| `≥ 72 小时且 < 168 小时`（3 至不足 7 天） | REMINDER | 接续提醒；简短回顾上次做到哪里及下一步 |
| `≥ 168 小时且 ≤ 360 小时`（7 至 15 天，含 15 天） | WARNING | 中断警告；建议先回顾当前任务、关键决定与未完成事项 |
| `> 360 小时`（超过 15 天） | LONG_GAP | 长期中断；建议先梳理交付目标、当前实现与剩余工作再继续 |

状态表格与看板字段下方按输出约定列出四条等级说明；字段值仅保留时长与英文等级。进入更高等级或用户回来接续时可在对话中简短提示，不额外扩展时间分区，不在每次对话重复警告，不另存提醒历史。

计划内暂停保留实际间隔，计划安排放当前工作或风险中，不扣掉暂停天数或误报为计划外异常。项目实际完成后，历时截至完成时间并停止连续性提醒；单个任务或本轮资料操作 DONE 不代表项目结束。之后有新工作时按实际恢复接续，保留原起项时间。

等级只影响提醒力度与恢复建议，不自动更改阶段、判定暂停或失败，不自动启动测试、重构或全项目重新规划。恢复读取已有依据按原授权进行，额外验证仍遵守验证门禁。
